使用与判定说明

常见问题及解答

1. 为什么求解器会推荐不符合已知条件的卡？

挑战卡不必是候选答案。某张卡虽然不符合已有线索，但它的六项特征可能更适合区分剩余候选，能够一次验证多个字段。求解器比较的是后续整体成功率和资源消耗，而不是只从候选答案中挑卡。

2. 为什么候选只剩几张，求解器仍然建议使用提示？

提示揭示的字段是随机的，但不消耗挑战次数。某些情况下，保留有限的挑战次数比立即猜测更有价值。求解器会综合当前候选分布、剩余题数和两类资源库存进行判断，并不固定采用“先提示”或“先挑战”。

3. 为什么候选只剩一张，推荐卡却不一定是这张卡？

正常情况下，如果该候选确实可以直接通关，求解器应优先推荐它。若出现其他推荐，可能是多张卡属于相同判定组、数据库与活动卡池存在误差，或者录入的挑战反馈存在矛盾。建议展开判定组并检查活动记录。

4. 为什么有多张卡六项信息完全相同？

游戏中存在六项判定完全相同的不同卡片。根据活动规则，只要选择其中任意一张进行挑战，就会被判定为正确答案。求解器会把这些卡归入同一个判定组。

5. 为什么六项都点亮了，却仍然没有通关？

这主要发生在灵摆卡上。目标为灵摆卡时，只要挑战卡命中其组成边框之一，边框项就会点亮，并揭示完整目标边框。因此可能出现六项全部点亮，但挑战卡完整边框与目标不同的情况；此时六项相符仍然有效，但不算猜中整张卡。

6. 灵摆卡的边框结果应该怎样录入？

边框点亮后，应选择游戏实际揭示的完整目标边框，例如“效果／灵摆”“超量／灵摆”或“仪式／灵摆”，不能只选择挑战卡自身的边框。求解器不会默认代选，以避免错误排除候选。

7. 为什么候选数量与游戏内实际情况不完全一致？

工具卡库已尽量与《大师决斗》游戏内数据库校准，但科乐美没有公开“卡片解码者”活动的完整抽题名单，活动可能额外排除少量特殊卡。因此候选范围仍可能存在很小误差。

8. 四种计算模式应该选哪个？

通常建议使用“综合期望”，它会兼顾当前收益、通关概率、信息价值和后续资源。“本次得分”偏向当前一手收益；“通关概率”偏向立即猜中；“信息量”偏向缩小候选范围，主要用于观察和研究。

9. 规模测试为什么较慢？并行数越高越好吗？

规模测试会反复调用与实操相同的求解策略，而不是使用简化随机策略，因此计算量较大。提高并行数会增加内存占用和线程竞争，速度通常不会按并行数成倍提升，一般推荐使用 4 路并行。

10. 工具会上传我的活动记录或操作数据吗？

不会。求解、规模测试和活动记录都在浏览器本地处理，导入和导出的文件也只由用户自行保存。网页仅使用 Cloudflare Web Analytics 统计匿名访问量和性能指标，不上传具体谜题记录或卡片选择。
