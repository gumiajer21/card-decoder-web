# 卡片解码者网页版

《游戏王 MASTER DUEL》“卡片解码者”活动的非官方辅助求解器。求解、演练、规模测试和活动记录全部在浏览器本地运行，无需安装或后端服务。

**B站 @Gumiajer 制作 · 免费分享**

**在线使用：<https://gumiajer21.github.io/card-decoder-web/>**

## 快速使用

1. 按游戏画面录入初始揭示的字段。
2. 点击“计算推荐行动”，按照推荐选择提示或挑战卡。
3. 挑战后勾选游戏中点亮的字段；若边框点亮，再选择游戏揭示的完整目标边框。
4. 完全猜中后进入下一题。浏览器会自动保存当前活动进度。

如需隔日或跨设备继续，可在“设置 → 导入／导出活动”中保存或导入 JSON，也可以使用逐项补录恢复旧行动。首次进入新题时，应先录入游戏给出的初始揭示；程序会在遗漏时给出保护提示。

## 功能

- 六项线索录入、挑战反馈和求解建议
- 按官方规则处理灵摆边框：目标为灵摆卡时，命中任一组成边框即相符，并记录游戏揭示的完整边框
- 六项点亮与整卡通关分开判定：灵摆组成边框可点亮并计入相符项，但完整边框不同不会误判通关
- 边框点亮后不再默认选择挑战卡边框，必须按游戏画面显式选择完整目标边框，避免组合边框被误录
- 活动记录导入／导出，以及逐步勾选式补录；撤销、重置和导入会同步刷新行动轨迹
- 完整数据库多条件筛选、排序和图格／列表浏览
- 演练模式合并原测试与小游戏流程，可切换目标卡已知／未知，并可随机或指定目标及初始揭示
- 1／2／4／8 路并行规模测试，可查看各分路状态和按题累计提示使用统计
- 可计算任意挑战卡的单步收益，并将自选卡与推荐卡放入“强制第一步”的策略价值对比
- 默认使用无外部依赖的仿卡面信息卡；也可从 jsDelivr 按编码分包、按需下载并缓存中文高清卡图
- 接近游戏内样式的目标卡／六项横条／挑战卡三栏展示，使用边框、属性、种族、等级、阶级、连接及攻守素材
- 活动轨迹按题显示初始揭示、提示和挑战行动链，仅长期保留当前活动与上一次活动
- 设置统一收纳活动配置、导入导出、主题、卡图、缓存、常见问题和版本记录；顶部保留 B站介绍视频、演练模式、规模测试和设置入口

## 当前版本重点

- 六项信息区改为目标卡、纵向判定条和猜测卡三栏布局，素材与游戏内显示方式更接近
- 增加滚动告示，并完善窄窗口下的顶部布局
- 中文高清卡图采用可选的 CDN 分包：首次查看时按需下载约 10–15 MB，并缓存在浏览器 IndexedDB 中
- 增加卡图缓存管理，可关闭自动下载、查看已缓存分包并一键清理；下载失败自动回退到仿卡

- 演练模式支持目标已知／未知、随机／指定目标及随机／指定初始揭示，方便复现实例或自行游玩
- 挑战区新增单卡收益分析；推荐区和挑战区均可加入策略价值对比
- 策略对比固定各卡为第一步，再以同一套后续提示／挑战策略树计算，不再只比较单步指标
- 修复收益面板出现后导致挑战卡面被裁切的问题，并补齐浅色主题对比度
- 实验性增强搜索及预算／深度实验功能暂不进入网页版
- 修正灵摆边框的非对称判定，并提供完整目标边框的显式选择
- 规模测试增加 1／2／4／8 路并行和各分路实时进度
- 将活动导入／导出移至醒目位置，并加入文件导入和逐项补录
- 数据库六项条件全部改为自由勾选，同项取并集、不同项取交集
- 候选区扩展为完整数据库，可按已知信息筛选和切换列表／图格
- 活动轨迹改为按题排列的行动链，只保留当前和上一次活动；记录窗口加宽以减少横向滚动
- 修复撤销后目标卡、猜测卡、卡图和活动轨迹未同步恢复的问题
- 正式模式增加初始揭示保护，演练模式记录独立且退出后自动清除
- 仿卡面按通常、效果、融合、同步、超量、连接和仪式显示对应边框色，并以不同图形区分等级、阶级和连接值

## 数据与隐私

- “大师决斗游戏内校准卡池”当前为 **9,058 张怪兽卡**。经游戏内确认，“优秀精灵”已从活动卡池权重中剔除，但同判定组的其他卡片仍保留。科乐美未公开本活动的完整抽题名单，候选范围仍可能随游戏更新发生少量变化。
- 所有求解、模拟和活动记录都在访问者的浏览器中处理；活动记录不会上传到项目服务器。
- 网页使用 Cloudflare Web Analytics 查看匿名访问量和性能指标，不用于识别具体用户。
- 主网页仓库不直接收录完整官方卡图集。用户主动启用中文高清卡图后，网页才会从独立公开资源仓库经 jsDelivr 下载所需分包，并保存在该浏览器的 IndexedDB 中；关闭此选项时只显示仿卡。

## 发布

仓库中的 `docs` 是完整部署目录。GitHub Pages 可直接从 `main` 分支的 `docs` 目录发布，不需要 Actions 工作流。

首次部署前，在 GitHub 仓库中打开：

1. `Settings` → `Pages`
2. 将 `Source` 设为 `Deploy from a branch`
3. Branch 选择 `main`，目录选择 `/docs`
4. 点击 `Save`

之后只需将更新推送到 `main` 分支，原网页链接会自动更新。若仍看到旧版，可等待几分钟后使用 `Ctrl + F5` 强制刷新。

### 维护中文卡图分包

卡图源目录默认位于相邻本地项目的 `dist/card-images-zh/00` 至 `99`。运行：

```powershell
.\tools\build-card-image-packs.ps1
```

脚本会在未纳入 Git 的 `release-assets/card-images-zh-v1` 中生成 100 个 ZIP 和 `manifest.json`。由于 GitHub Release 的跨域重定向不适合作为网页运行时资源源，需将这些文件上传到公开仓库 `gumiajer21/card-decoder-images`，并创建标签 `v1`。网页会从 `https://cdn.jsdelivr.net/gh/gumiajer21/card-decoder-images@v1/` 读取：

- `card-images-zh-00.zip` 至 `card-images-zh-99.zip`
- `manifest.json`

图片更新时应使用新的版本标签，并同步修改 `docs/app.js` 中的 CDN 地址，避免旧缓存和新资源混用。GitHub Release 上传脚本仍可作为本地备份发布工具，但不再作为网页运行时资源源。

`publish-card-image-release.ps1` 仅用于制作 GitHub Release 备份，不是网页当前的运行时卡图来源。
